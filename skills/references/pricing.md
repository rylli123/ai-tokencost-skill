# 各厂商的计费口径（改价前必读）

同一个「输入」，不同厂商的账单口径不一样；错配会让徽标系统性偏高或偏低。

## DeepSeek

| 桶 | 计费 |
|---|---|
| 输入（缓存命中） | 命中价 |
| 输入（未命中） | 未命中价；缓存写入不单独收费 |
| 输出 | 输出价 |
| 分时 | 北京时间**周一至周五 09:00–12:00、14:00–18:00 为高峰**，其余（含周末、法定节假日）为空闲，空闲 = 高峰 × 50% |
| 附加 | Search / Fetch 按成功请求计费（¥5 / 1,000 次），不计入 token |

`pricing.json` 里 `band: "cn-business"`，`peakMultiplier: 2`，`offPeakMultiplier: 1`。
`holidays` 默认空数组——法定节假日每年由国务院公布，按年补日期即可（`"2026-10-01"` 这种格式）。

## Anthropic（Claude）

| 桶 | 计费 |
|---|---|
| 输入（未命中） | 基础输入价 |
| 缓存写入（5m TTL） | 基础输入价 × 1.25 |
| 缓存写入（1h TTL） | 基础输入价 × 2 |
| 缓存读取 | 基础输入价 × 0.1 |
| 输出 | 输出价 |
| 分时 | 无 |

所以 Claude 的 `cacheHit` 是基础价的 0.1 倍、`cacheWrite` 是 1.25 倍，两个都要填，不能都塞进 miss。

## OpenAI

| 桶 | 计费 |
|---|---|
| 输入（未命中） | 基础输入价 |
| 缓存输入 | 基础价 × 0.1（自动缓存，不额外收写入费） |
| 输出 | 输出价 |
| 分时 | 无 |

`cacheWrite: 0`。

## Google（Gemini）

| 桶 | 计费 |
|---|---|
| 输入 / 输出 | 按档位（部分模型 >200k 上下文进入高价档） |
| 上下文缓存 | 缓存 token 按「token·小时」计费 + 存储费，与传统「命中价」模型不同 |
| 分时 | 无 |

Gemini 的缓存是**存储型**，本插件的三桶模型只能近似：把 `cacheHit` 填成缓存读取等效单价，并在 `source` 里注明。若要精确核算，建议单独写一个 provider 适配，而不是硬塞进当前模型。

## 加一条价目的检查表

- [ ] `id` 与模型 id 完全一致（小写，用 `-`）——这是主键
- [ ] 旧名、别名、日期后缀变体放 `aliases`
- [ ] `currency` 只能是 `CNY` 或 `USD`
- [ ] 三个价都是**每百万 tokens**，别写成每千
- [ ] Anthropic 记得填 `cacheWrite`
- [ ] `band` 没有分时定价就写 `null`
- [ ] `status`：自己对着官网核过填 `verified`，否则 `unverified`
- [ ] `source` + `checkedAt` 填齐，方便以后回查
- [ ] `node scripts/gen-pricing.mjs && node scripts/validate.mjs`

## 怎么核对一个价格

1. 打开厂商官方定价页（不要用第三方汇总站）
2. 记下页面上的**币种**与**计价单位**（per 1M tokens 还是 per 1K）
3. 把 `checkedAt` 写成当天
4. 把页面 URL 填进 `source`
5. 只有亲眼核对过的才把 `status` 改成 `verified`
